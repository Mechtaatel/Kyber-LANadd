# Тестовая сборка LAN / Radmin

Распакуйте весь архив в новую папку. Не переносите отдельно exe или DLL и не
накладывайте комплект на старую установку. В Windows запускайте kyber_launcher.exe.
Папка lan-module должна оставаться рядом с программой. Её модуль закреплён:
официальный автоапдейтер не заменяет его. Для обновления используйте новый полный
комплект этого ответвления. У обоих игроков должна быть эта сборка.

В HOST собственный LAN-only сервер отображается через локальное соединение с
игрой: можно смотреть игроков, менять команды, кикать и отправлять консольные
команды без Kyber API. Баны аккаунтов и назначение модераторов в автономном LAN
недоступны. Если мод содержит неподдерживаемую таблицу локализации, загрузчик
пропускает её с сообщением в логе вместо бесконечного повтора. Это не заменяет
проверку запуска конкретного набора модов на Linux/Wine.

## Radmin

Оба компьютера должны быть в одной сети Radmin. Разрешите входящие UDP 25200
(игра) и 25202 (обнаружение) для игры в брандмауэре только от доверенных LAN/VPN
адресов. Не отключайте брандмауэр/антивирус целиком и не открывайте порты на роутере.
После загрузки карты обновите браузер и выберите REGION → LAN.

В журнале хоста должна появиться строка `[LAN] Discovery listening on UDP 25202`.
При подключении журнал лаунчера должен содержать `Joining server directly over LAN`,
а не `Joining server with proxy`. Одна запись одновременно публичного и локального
сервера получает регион LAN и прямой маршрут. Официальные серверы остаются выше LAN,
LAN — выше серверов друзей.

Публичный сервер всё ещё требует действующий токен Kyber, даже при прямом маршруте.
Для независимости от сервисов Kyber включите LAN ONLY на хосте и войдите через
LAN — WITHOUT KYBER SERVICES на клиенте. При смене онлайн/LAN-only перезапустите игру.
EA/Maxima, лицензия, игра и совместимые игровые ресурсы всё равно необходимы;
дополнительные клиентские косметические моды допустимы.

## Linux x86_64

По официальной инструкции установите Docker и игру. Готовый образ
`registry.kyber.gg/kyber-server:latest` содержит Wine/Maxima, но его CLI и DLL
официальные и не содержат наши LAN-исправления. Мы не выдаём собственный образ:
смонтируйте весь распакованный архив CLI и запустите наш скрипт вместо штатного
entrypoint образа:

```sh
unzip kyber-cli-linux-x64.zip
chmod +x kyber-cli-linux-x64/kyber_cli kyber-cli-linux-x64/maxima-bootstrap kyber-cli-linux-x64/wine-helper.exe
docker run --rm --network host \
  -e MAXIMA_CREDENTIALS='email:password' \
  -e KYBER_SERVER_NAME='Мой LAN сервер' \
  -e KYBER_MAP_ROTATION='<base64 из нашего лаунчера>' \
  -e KYBER_LAN=1 \
  -v "$PWD/kyber-cli-linux-x64:/opt/kyber-lan:ro" \
  -v '/путь/к/Battlefront II:/mnt/battlefront' \
  --entrypoint /bin/bash registry.kyber.gg/kyber-server:latest \
  /opt/kyber-lan/run-lan-docker-overlay.sh
```

`KYBER_MAP_ROTATION` можно опустить для карты по умолчанию. Для модов добавьте
`-e KYBER_MOD_FOLDER=/mnt/mods` и монтирование папки коллекции в `/mnt/mods`.
Токен Kyber в LAN-only не требуется; авторизация EA и лицензия игры остаются.
Смонтированная папка игры должна допускать запись `vivoxsdk.dll`. Для LAN
используется `--network host`. Экспорт ротации нашего лаунчера содержит строки
`mode;map` в base64, хотя официальный текст называет формат JSON. При явном
`--game-path` файл игры проверяется напрямую без требования записи в реестре EA.
Работа с меняющимся тегом `latest` требует проверки на Linux.
Как и оригинальный `kyber-cli`, сервер читает список вложенных `.fbmod` из
`.kbcollection`. В вашем случае там записаны отображаемые имена, а физические
файлы из `.fbcollection` называются иначе. На хосте Linux один раз создайте
исправленные метаданные, не меняя моды или порядок загрузки:

```sh
python3 repair-server-collection.py /path/to/old.kbcollection \
  --mod-folder /path/to/mounted/mods \
  --output /path/to/repaired.kbcollection
```

Проверьте новый файл, затем вынесите старую `.kbcollection` за пределы
смонтированной папки и положите туда исправленную. В папке должен остаться
ровно один файл `.kbcollection`. Внутри контейнера каждый `.fbmod` должен
читаться по точному относительному пути под `KYBER_MOD_FOLDER`. Файлы могут быть на хосте, но
оказаться в другой папке контейнера, вложенной директории или отличаться
регистром букв (в Linux он значим). Новый CLI показывает ожидаемые пути и
образцы видимых файлов и прекращает запуск, если пути не совпадают.
Дополнительные клиентские
косметические моды допустимы; должны совпадать ресурсы, влияющие на уровень.
Если один сервер виден по обычной LAN и Radmin, сначала используйте
обычный LAN-адрес: ответ discovery на 25202 ещё не гарантирует, что через VPN
разрешён игровой UDP 25200.
Для постоянного сервера замените `--rm` на `-d --restart unless-stopped` и
смотрите запуск через `docker logs -f`. Подробное логирование CLI по умолчанию
отключено, чтобы не записывать пароль EA вместе с аргументами запуска.

Windows-кросс-сборка не заменяет проверку запуска на Linux. Перед запуском
убедитесь, что `kyber_cli` и `maxima-bootstrap` имеют право на исполнение.
FRB в Dart, Rust и генераторе закреплён на 2.11.1. `librust_lib.so` лежит
в комплекте и загружается независимо от текущего каталога.
CLI — нативная Linux-программа, а игра и Kyber.dll — Windows-компоненты.
Библиотека Maxima уже связана с CLI; отдельно устанавливать приложение Maxima
не нужно. Для Windows-игры всё равно требуется Wine-совместимый runtime.
Исходный Docker-образ уже содержит Wine-GE и выбирает его через
MAXIMA_WINE_COMMAND. Сохраняйте рабочие настройки сервера: не меняйте runtime
или prefix и не задавайте DISPLAY только из-за сообщений Wine в логе.
MAXIMA_DISABLE_WINE_VERIFICATION отключает автоматическую проверку runtime,
если эта переменная присутствует, даже со значением 0.
Для хостинга нужны игра, настройки EA/Maxima и модуль из lan-module.
Пример запуска и systemd приведён в LAN.md; замените --module-path своим абсолютным
путём к lan-module. wine-helper.exe должен оставаться рядом с CLI.
Это помощник Maxima для поиска процесса игры и внедрения DLL.

В новых комплектах SHA256SUMS содержит контрольные суммы файлов, а
release-manifest.json — состав комплекта и состояние исходников при упаковке.
Перед установкой проверьте файлы по SHA256SUMS. Для отчёта об окружении выполните
`sh diagnose-linux.sh` от того же пользователя
и с теми же переменными окружения, что и сервис. Скрипт не запускает игру,
не меняет runtime/DISPLAY и не читает учётные данные.

## Известный сбой запуска на Linux

В логе от 24.09.2026 игра после внедрения DLL падает при чтении адреса 0x8
в инструкции 0x14541CEA0. Точная причина по этому фрагменту не установлена.
Сообщение `Kyber started` в старых комплектах появляется при запросе лицензии игрой;
оно не подтверждает загрузку карты или открытие LAN-портов. Исправление повтора
локализации не является доказанным исправлением этого ACCESS_VIOLATION.
Предупреждения FreeType и DISPLAY сами по себе также не устанавливают причину.

Контрольные запуски на Linux воспроизвели тот же сбой без модов и с отключённым
ModLoader. Это исключает моды как необходимое условие этого падения.
Экспериментальное исправление загрузки управляемого Proton/umu убрано: исходный
Docker-путь использует уже встроенный Wine-GE, а смена runtime не была доказанным
исправлением падения BFII. CLI больше не выдаёт событие лицензии за успешный
запуск сервера. Проверяйте с прежними переменными и настройками сервиса, оставив
DISPLAY и WAYLAND_DISPLAY незаданными. DLL собрана на Windows/MSVC, но запуск
игры на Linux и устранение ACCESS_VIOLATION пока не подтверждены.

Проверки локального UDP-протокола не подтверждают полноценную игру между двумя
компьютерами. Перед постоянным хостингом проверьте вход, смену карты и переподключение.
